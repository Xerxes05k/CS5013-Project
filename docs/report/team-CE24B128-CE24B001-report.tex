\section{Executive summary}

Jamuna Hostel lends a small pool of cycles through a paper register at the gate. Residents cannot see which cycles are free, the 24-hour and 3-per-week limits are not enforced, and a broken cycle is simply handed to the next person. We shipped a Java/Spring Boot web app (Thymeleaf, SQLite) used on residents' own phones: book a free cycle after OCR reads your ID card, confirm pickup and return by typing your passcode while the guard (who has no device) watches, and tick the parts the guard found broken; a broken critical part sends the cycle to repair. The GS sees usage hours and a maintenance list with a Repaired button. 126 automated tests pass. Scope change: the OpenNLP comment classifier was dropped for per-part cycle condition, which mid-demo feedback asked for.

Stakeholder verdict: accepted by the Jamuna GS (8 Nov 2026), with the hostel setup to follow once the physical side is ready at his end. Since 8 Nov it runs live at \url{https://3-26-193-82.sslip.io} on an AWS Free plan server (ADR 0008); the Docker image is for grading.

\section{Known limitations}

\begin{itemize}[leftmargin=*,nosep]
  \item \textbf{OCR on cards other than the one we tested.} Evidence is one real IIT Madras card (9 of 10 photos) and 18 synthetic ones; glare or another layout fails the scan, so the resident types their roll number after 3 tries; a misread only costs a retry, as the roll must match the login.
  \item \textbf{Safety rules that rely on SQLite's single connection.} ``One open rental per resident'' holds only because the pool has one connection; SQLite foreign keys are off, so hand-written SQL can leave orphans.
  \item \textbf{Resident comments raise no flags.} With the classifier cut, a comment like ``brakes feel weak'' reaches the GS only as text; the cycle stays bookable until a guard marks it broken.
\end{itemize}
